## 1. Architectural Overview & Single Identity Principle

ASTRION is architected as **one unified AI mentor with one central orchestrator, shared permission-aware student context, and dynamically activated specialist capabilities**. 

Agents in ASTRION never operate as independent, disconnected chatbots or distinct public personas. A student communicates solely with **ASTRION**. The orchestrator (`AIMentorOrchestrator`) transparently activates specialist capabilities across three distinct tiers:
1. **Agent Layer A: Domain Specialist Agents** (8 canonical specialist identities)
2. **Agent Layer B: Student Intelligence Agents** (6 continuous learner-modeling capabilities)
3. **Agent Layer C: Supporting Intelligence Agents** (5 safety, quality, retrieval, and handoff capabilities)

All agents consume context generated by `PermissionAwareContextBuilder`, adhere to student consent governed by `StudentConsentService`, and write persistent facts to the PostgreSQL `student_intelligence_evidence` ledger.

## 2. Agent Layer A: Domain Specialist Agents

The 8 canonical domain specialists maintain fixed responsibilities and contracts. System design is strictly mapped to ATLAS, and career strategy is strictly mapped to VECTRA.

### Bounded Multi-Specialist Routing Specification
To prevent runaway latency and recursive agent loops:
- The orchestrator resolves **at most one primary specialist** and **at most one complementary secondary specialist** per turn via `SpecialistRegistry.resolveSecondarySpecialist`.
- Cross-domain interactions (e.g. CIPHER + ATLAS for distributed systems coding, or PRISM + VECTRA for career-targeted resume auditing) enrich the prompt with domain invariants without spawning subagents.

## 3. Agent Layer B: Student Intelligence Agents

Student Intelligence Agents operate directly on the student graph and memory services to maintain an accurate, non-invasive understanding of the learner.

### 3.1 Adaptive Learning Agent (`adaptive-learning-agent`)
- **Layer:** Student Intelligence
- **Implementation:** `lib/ai-mentor/agents/adaptive-learning-agent.ts`
- **Execution Mode:** Deterministic DAG traversal against `CANONICAL_TAXONOMY`
- **Required Consent:** `service_personalization`
- **Key Responsibilities:**
  - Differentiates **demonstrated / assessed mastery** (scored via verified concept checks or coding tasks) from **inferred or self-reported mastery**.
  - Traverses the skill dependency graph to detect missing prerequisite concepts before advancing to complex topics.
  - Dynamically computes a pacing factor (`accelerate`, `standard`, `scaffold_foundations`).
- **Input:** Student message, target topic, verified skill nodes from `AuthorizedStudentContext`.
- **Output:** Current mastery level, prerequisite alerts, next recommended topic, and pacing calibration.

### 3.2 Student Profiler & Memory Agent (`student-profiler-agent`)
- **Layer:** Student Intelligence
- **Implementation:** `lib/ai-mentor/agents/student-profiler-agent.ts`
- **Execution Mode:** Deterministic memory filter & provenance auditor
- **Required Consent:** `student_memory`, `service_personalization`
- **Key Responsibilities:**
  - Retrieves active memories and preferences from `StudentMemoryService`.
  - Filters out expired or revoked memories.
  - **Zero Psychological Profiling Policy:** Strictly blocks inferences regarding emotional temperament, psychiatric state, or hidden personality traits.
- **Input:** Student ID, conversation focus area, memory bank.
- **Output:** Authorized preferences, explicit career goals, memory provenance audit (student-confirmed vs system-observed counts).

### 3.3 Learning-Gap Detector (`learning-gap-agent`)
- **Layer:** Student Intelligence
- **Implementation:** `lib/ai-mentor/agents/learning-gap-agent.ts`
- **Execution Mode:** Deterministic competency benchmarking
- **Required Consent:** `service_personalization`
- **Key Responsibilities:**
  - Compares the student's demonstrated skill scores against industry competency benchmarks (e.g., SDE-1, Distributed Systems Engineer).
  - Categorizes gaps into **confirmed gaps** (tested and below threshold) and **suspected gaps** (untested dependencies).
  - Generates concrete, actionable remediation topics for each identified gap.
- **Input:** Student skill graph, target engineering role.
- **Output:** Confirmed gaps with severity ratings, suspected gaps, benchmark role, overall gap severity.

### 3.4 Goal & Roadmap Planner (`goal-roadmap-agent`)
- **Layer:** Student Intelligence
- **Implementation:** `lib/ai-mentor/agents/goal-roadmap-agent.ts`
- **Execution Mode:** Deterministic milestone generator
- **Required Consent:** `service_personalization`
- **Key Responsibilities:**
  - Translates student goals into structured 6-to-12-week milestone roadmaps.
  - Preserves critical prerequisite dependencies (e.g. Arrays/Strings → Two Pointers → Dynamic Programming).
  - Assigns estimated effort hours and tangible deliverables to each milestone.
  - Never mutates primary goals without explicit student confirmation.
- **Input:** Student target role, verified skills, active milestones.
- **Output:** Total weeks, milestone sequence, deliverables, estimated effort hours, critical path alerts.

### 3.5 Accountability & Check-In Agent (`accountability-agent`)
- **Layer:** Student Intelligence
- **Implementation:** `lib/ai-mentor/agents/accountability-agent.ts`
- **Execution Mode:** Deterministic check-in scheduler
- **Required Consent:** `service_personalization`
- **Key Responsibilities:**
  - Tracks milestone progress and schedules constructive habit check-ins.
  - **Non-Manipulative Tone Principle:** Completely avoids guilt-inducing language, fear of falling behind, or psychological pressure.
  - Disables check-in prompts immediately if the student revokes personalization consent.
- **Input:** Active milestones, student consent state.
- **Output:** Pending check-ins, supportive prompts, accountability tone classification.

### 3.6 Engagement & Activity Intelligence Agent (`engagement-agent`)
- **Layer:** Student Intelligence
- **Implementation:** `lib/ai-mentor/agents/engagement-agent.ts`
- **Execution Mode:** Deterministic interaction depth evaluator
- **Required Consent:** `analytics_evaluation`, `service_personalization`
- **Key Responsibilities:**
  - Computes learning depth scores based on verified concept checks and technical discussions.
  - Distinguishes genuine mastery from superficial vanity activity (e.g. repeated page refreshes or trivial queries).
  - Strictly operates on authorized session history without covert background surveillance.
- **Input:** Conversation history, verified skill demonstrations.
- **Output:** Concept verification ratio, learning depth score (0.0-10.0), mastery distinction summary.

## 4. Agent Layer C: Supporting Intelligence Agents

Supporting Intelligence Agents safeguard platform boundaries, guarantee factual accuracy, retrieve verified educational resources, and coordinate human mentor escalations.

### 4.1 Safety & Guardrail Agent (`safety-guardrail-agent`)
- **Layer:** Supporting Intelligence
- **Implementation:** `lib/ai-mentor/agents/safety-guardrail-agent.ts`
- **Execution Mode:** Deterministic multi-stage regex and semantic sanitizer
- **Required Consent:** None (Mandatory system-level gate)
- **Key Responsibilities:**
  - **Clinical Crisis Boundary:** Detects expressions of self-harm or psychological crisis and immediately returns the verified national Tele-MANAS helpline notice (`14416` / `1800-891-4416`).
  - **Prompt-Injection Defense:** Detects and neutralizes jailbreak tokens (`<|im_start|>`, `<|system|>`, instruction overrides, and role spoofing).
  - Treats all user uploads and external documents as untrusted input.
- **Input:** Raw user message.
- **Output:** Safety status, crisis notice (if applicable), sanitized input text, detected policy violations.

### 4.2 Evaluator / Critic Agent (`evaluator-critic-agent`)
- **Layer:** Supporting Intelligence
- **Implementation:** `lib/ai-mentor/agents/evaluator-critic-agent.ts`
- **Execution Mode:** Deterministic quality gate & consistency checker
- **Required Consent:** None (Internal quality assurance)
- **Key Responsibilities:**
  - Audits candidate responses for factual grounding, logical completeness, and cross-specialist consistency.
  - **Zero-Fabrication Policy:** Flags suspicious, unverified metrics on resumes (e.g. "increased revenue by 1000%").
  - Requires Big-O complexity analysis when algorithmic solutions are proposed.
- **Input:** User query, synthesized response, active specialists, retrieved sources.
- **Output:** Quality score (0.0-10.0), pass/fail quality gate, detected contradictions, refinement suggestions.

### 4.3 Resource & Opportunity Retriever (`resource-retriever-agent`)
- **Layer:** Supporting Intelligence
- **Implementation:** `lib/ai-mentor/agents/resource-retriever-agent.ts`
- **Execution Mode:** Hybrid inverted-index RAG lookup (`KnowledgeRAGService`)
- **Required Consent:** `service_personalization`
- **Key Responsibilities:**
  - Retrieves verified educational resources, documentation, and curriculum guides.
  - Attaches source publisher and freshness metadata to every retrieved item.
  - **Zero Fabricated Links Policy:** Strictly prohibits generating ungrounded external URLs.
- **Input:** User message, active topic, focus area.
- **Output:** Verified resource items, source citations with URLs/IDs, verification status.

### 4.4 Communication-Gap Agent (`communication-gap-agent`)
- **Layer:** Supporting Intelligence
- **Implementation:** `lib/ai-mentor/agents/communication-gap-agent.ts`
- **Execution Mode:** Deterministic structural and clarity analyzer
- **Required Consent:** `service_personalization`
- **Key Responsibilities:**
  - Evaluates user-submitted technical writing, problem descriptions, or mock interview answers for clarity, structure, and ambiguity.
  - Suggests concrete improvements (e.g. separating dense paragraphs into bullet points, adding error messages).
  - Never judges the student's personal communication ability or social competence.
- **Input:** User message or technical passage.
- **Output:** Clarity score (0.0-10.0), structural observations, suggested improvements.

### 4.5 Mentor Collaboration Agent (`mentor-collaboration-agent`)
- **Layer:** Supporting Intelligence
- **Implementation:** `lib/ai-mentor/agents/mentor-collaboration-agent.ts`
- **Execution Mode:** Consent-governed escalation evaluator (`HumanEscalationService`)
- **Required Consent:** `mentor_sharing`
- **Key Responsibilities:**
  - Evaluates whether persistent struggle (e.g. multiple repeated concept failures) warrants human mentor consultation.
  - Generates a minimized, privacy-preserving struggle briefing summarizing verified gaps.
  - Prepares actionable human booking options without exposing the entire student intelligence graph.
- **Input:** Student ID, user message, relevant skills from context, focus area.
- **Output:** Human handoff eligibility, recommended mentor specialty domains, sanitized struggle briefing.
