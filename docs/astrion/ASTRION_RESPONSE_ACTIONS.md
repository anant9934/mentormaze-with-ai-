## 1. Overview of Structured Response Actions

In ASTRION, mentorship turns are never limited to raw conversational prose. Every response generated by **ASTRION CORE** includes a comprehensive set of **Structured Action Payloads** that transform advice into concrete, interactive student outcomes.

These payloads are emitted by the orchestrator (`StructuredTurnResponse`), transmitted via Server-Sent Events (SSE) by `/api/ai-mentor`, and rendered as rich UI action cards in `components/ai-mentor/ai-mentor-conversation.tsx`.

## 2. Action Category 1: Study Plan / Roadmap (`msg.studyPlan`)

### Purpose
Provides structured milestone pacing for students navigating multi-week interview preparation or skill mastery.

### TypeScript Schema
```typescript
export interface StudyPlanAction {
  targetRole: string;
  totalWeeks: number;
  currentMilestone: {
    weekNumber: number;
    title: string;
    objectives: string[];
    deliverables: string[];
    status: "pending" | "in_progress" | "completed";
  };
  milestones: {
    weekNumber: number;
    title: string;
    objectives: string[];
    deliverables: string[];
    status: "pending" | "in_progress" | "completed";
  }[];
}
```

### Example Payload
```json
{
  "targetRole": "Distributed Systems Engineer",
  "totalWeeks": 6,
  "currentMilestone": {
    "weekNumber": 1,
    "title": "Algorithmic Invariants & Time Complexity",
    "objectives": ["Prove loop invariants", "Derive Big-O bounds"],
    "deliverables": ["Written proofs for 4 sorting invariants"],
    "status": "in_progress"
  },
  "milestones": [
    {
      "weekNumber": 1,
      "title": "Algorithmic Invariants & Time Complexity",
      "objectives": ["Prove loop invariants"],
      "deliverables": ["Written proofs for 4 sorting invariants"],
      "status": "in_progress"
    },
    {
      "weekNumber": 2,
      "title": "Trees, Graphs & Traversal Invariants",
      "objectives": ["BFS/DFS invariants", "Topological sort"],
      "deliverables": ["Implemented topological sorter with cycle detection"],
      "status": "pending"
    }
  ]
}
```

### UI Presentation & Interaction
- Rendered as an emerald-bordered roadmap card beneath the mentor's answer.
- Displays target role, total duration pill, and chronological milestone rows.
- Each milestone features status pills (`in_progress`, `completed`, `pending`) and deliverables.
- Clicking a milestone prompts ASTRION to generate a deep-dive focus session for that week.

## 3. Action Category 2: Progress & Skill-Gap Insights (`msg.progressInsights`)

### Purpose
Provides transparent feedback on demonstrated competencies vs targeted gaps, distinguishing verified strengths from suspected gaps without clinical judgment.

### TypeScript Schema
```typescript
export interface ProgressInsightsAction {
  masteryLevel: "foundational" | "intermediate" | "advanced";
  confirmedStrengths: string[];
  confirmedGaps: {
    skillName: string;
    gapType: string;
    remediation: string;
  }[];
  suspectedGaps: {
    skillName: string;
    gapType: string;
  }[];
}
```

### Example Payload
```json
{
  "masteryLevel": "intermediate",
  "confirmedStrengths": [
    "Arrays & Strings Invariants",
    "PostgreSQL Index Optimization"
  ],
  "confirmedGaps": [
    {
      "skillName": "Dynamic Programming",
      "gapType": "missing_prerequisite",
      "remediation": "Practice 1D space-optimized memoization state transitions."
    }
  ],
  "suspectedGaps": [
    {
      "skillName": "Distributed Consensus (Raft)",
      "gapType": "untested_dependency"
    }
  ]
}
```

### UI Presentation & Interaction
- Rendered with an analytics icon, showing current mastery level.
- **Demonstrated Strengths:** Displayed as emerald checkmark badges (`✓ Arrays & Strings`).
- **Targeted Gaps & Remediation:** Displayed in soft amber callout boxes with specific remediation steps.

## 4. Action Category 3: Curriculum Resources & Opportunities (`msg.resources`)

### Purpose
Surfaces authoritative curriculum references and documentation matching the student's topic, enforcing the **Zero Fabricated Links** policy.

### TypeScript Schema
```typescript
export interface ResourceActionItem {
  id: string;
  title: string;
  category: "course" | "documentation" | "benchmark" | "competition";
  provider: string;
  urlOrRef: string;
  freshnessDate: string;
  relevanceScore?: number;
}
```

### Example Payload
```json
[
  {
    "id": "res-doc-ds-01",
    "title": "Designing Data-Intensive Applications — Caching Topologies",
    "category": "documentation",
    "provider": "MentorMaze Curriculum Standard",
    "urlOrRef": "https://mentormaze.aitathastu.com/resources/caching-topologies",
    "freshnessDate": "2026-Q1"
  },
  {
    "id": "res-course-02",
    "title": "MIT 6.824: Distributed Systems Engineering Notes",
    "category": "course",
    "provider": "MIT OpenCourseWare",
    "urlOrRef": "https://pdos.csail.mit.edu/6.824/",
    "freshnessDate": "2026-Q1"
  }
]
```

### UI Presentation & Interaction
- Rendered in a clean 2-column card grid with provider badge, freshness stamp, and "Verified" label.
- Clicking an external resource opens the verified link in a secure new tab (`rel="noopener noreferrer"`).

## 5. Action Category 4: Accountability Check-Ins (`msg.reminders`)

### Purpose
Fosters positive learning consistency through student-scheduled, non-manipulative habit prompts.

### TypeScript Schema
```typescript
export interface ReminderActionItem {
  milestoneTitle: string;
  prompt: string;
  scheduledTime: string;
}
```

### Example Payload
```json
[
  {
    "milestoneTitle": "Dynamic Programming State Transitions",
    "prompt": "How did your focus session go on 1D space optimization? Share any recurrence relations you'd like to verify together.",
    "scheduledTime": "Flexible / Student-initiated"
  }
]
```

### UI Presentation & Interaction
- Rendered in a soft green accountability container with a bell icon.
- Copy emphasizes growth and self-paced check-ins; strictly prohibits guilt-based language.

## 6. Action Category 5: Human Mentor Consultation Handoff (`msg.mentorHandoff`)

### Purpose
Coordinates optional escalation to verified human mentors when persistent learning struggles or high-stakes placement decisions warrant expert intervention.

### TypeScript Schema
```typescript
export interface MentorHandoffAction {
  eligible: boolean;
  domains: string[];
  sanitizedBriefing: string;
}
```

### Example Payload
```json
{
  "eligible": true,
  "domains": ["Distributed Systems", "Database Internals"],
  "sanitizedBriefing": "Student requested advanced guidance on distributed systems invariants. Verified gaps: Dynamic Programming, Cache Invalidation Topologies."
}
```

### UI Presentation & Interaction
- Rendered as an emerald gradient card with an "Eligible" badge and domain pills.
- Displays a privacy-sanitized briefing summary (protecting student personal details).
- Features a single-click button: **"Request Mentor Connection"**, which queues a mentor booking dialogue.
