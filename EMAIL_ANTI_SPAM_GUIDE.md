## 1. Executive Summary

Email deliverability is not determined by luck—it is dictated by strict technical standards enforced by Google Mail, Yahoo Mail, and Microsoft 365 (including the **February 2024 Google & Yahoo Mandatory Sender Requirements**).

When emails land in the **Spam / Junk folder**, it is almost always caused by one or more of these technical deficiencies:
1. **Missing or Non-Compliant Unsubscribe Headers:** Google demotes emails lacking RFC 8058 one-click unsubscribe headers.
2. **Untrusted Message-ID:** Defaulting to `@localhost` or unverified hostnames triggers SpamAssassin and Gmail anti-abuse filters.
3. **SPF / Return-Path Mismatch:** The SMTP envelope sender must align with the `From:` header.
4. **Poor HTML-to-Text Ratio or Missing Plain Text:** Sending HTML-only without a matching `text/plain` alternative causes heavy spam scoring.
5. **Missing Physical Postal Address:** Required by the CAN-SPAM Act, GDPR, and Google Postmaster rules.
6. **Trigger Words / Broken Markup:** ALL-CAPS subjects, zero-font-size hidden text, or broken CSS.

MentorMaze's email architecture has been updated to systematically address every one of these factors.

## 2. Technical Measures Implemented in MentorMaze

### A. RFC 8058 & RFC 2369 One-Click Unsubscribe
Marketing and mailing-list emails dispatched through `sendEmailDirect` automatically include:
```http
List-Unsubscribe: <https://mentormaze.aitathastu.com/api/email/unsubscribe?token=...>, <mailto:hellomentormaze@gmail.com?subject=unsubscribe>
List-Unsubscribe-Post: List-Unsubscribe=One-Click
```
* **Why this prevents spam:** Google and Yahoo display a native "Unsubscribe" button next to the sender name in the Gmail header for bulk messages.
* **Selective Application:** Transactional security emails (password resets, verification, booking invoices) explicitly exclude this header to prevent confusion and protect critical alerts.

### B. Authenticated Domain Message-ID (No `@localhost`)
Previously, standard Nodemailer configurations defaulted to the server's local machine name (e.g. `<...@localhost>`), which is an instant spam trigger in Gmail.
MentorMaze now generates an RFC 5322 compliant message ID aligned with the active sender domain (`gmail.com` or custom domain):
```typescript
const domain = config.fromEmail.includes("@gmail.com") ? "gmail.com" : "mentormaze.aitathastu.com";
const customMessageId = `<${Date.now()}.${crypto.randomBytes(8).toString("hex")}@${domain}>`;
```

### C. SPF Alignment & Envelope Sender Matching
The SMTP envelope sender is explicitly locked to the authenticated SMTP user:
```typescript
envelope: {
  from: config.fromEmail, // hellomentormaze@gmail.com
  to: options.to,
}
```
* When sending through `smtp.gmail.com:465` with SSL, Google automatically signs the message with its own DKIM key (`d=gmail.com`) and passes SPF (`v=spf1 include:_spf.google.com ~all`). Note: Signing for a custom domain requires Google Workspace or a dedicated transactional provider.

### D. Google Postmaster Tools `Feedback-ID` Header
MentorMaze attaches Google-standard tracking headers for reputation reporting:
```http
Feedback-ID: templateId:category:mentormaze:production
Auto-Submitted: auto-generated
X-Auto-Response-Suppress: OOF, AutoReply
```
* This explicitly marks notifications as legitimate user-triggered transactional messages, preventing auto-reply loops and informing spam filters of the message intent.

### E. Physical Postal Address
Every email generated by `lib/email/shell.ts` includes a configurable physical footer:
```
${process.env.BUSINESS_MAILING_ADDRESS || "MentorMaze by AI Tathastu • Bengaluru, Karnataka, India"}
Official Communications: hellomentormaze@gmail.com
```

### F. Dual-Format Multipart (HTML + Plain Text)
Every single template in `lib/email/templates/registry.ts` compiles both:
* **Table-based HTML** with inline styles (no unsupported CSS classes)
* **Clean Plain Text** (`text/plain`) alternative

## 3. Recommended Phased DNS Records for Custom Domain (`@mentormaze.aitathastu.com`)

When transitioning from `hellomentormaze@gmail.com` to an enterprise custom domain (e.g., `noreply@mentormaze.aitathastu.com`), configure the following 3 DNS TXT records.

### 1. SPF (Single Record Rule — RFC 7208)
Never create multiple SPF records; merge all authorized sending IP ranges into one:
```text
v=spf1 include:_spf.google.com ~all
```

### 2. DKIM (DomainKeys Identified Mail — RFC 6376)
Generate a 2048-bit RSA key inside Google Workspace Admin Console (or your transactional provider):
```text
Host:  google._domainkey.mentormaze.aitathastu.com
Value: v=DKIM1; k=rsa; p=MIIBIjANBgkqhkiG9w0BAQEFAAOCAQ8...
```

### 3. DMARC Phased Rollout (RFC 7489)
* **Initial Phase (Monitoring):** Start with `p=none` to collect reports without dropping emails:
  ```text
  Host:  _dmarc.mentormaze.aitathastu.com
  Value: v=DMARC1; p=none; rua=mailto:dmarc-reports@mentormaze.aitathastu.com; pct=100
  ```
* **Enforcement Phase:** Once all legitimate sending sources pass authentication, escalate to `p=quarantine` and finally `p=reject`.
